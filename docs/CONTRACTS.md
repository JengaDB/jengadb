# Shared contracts — draft v1

Discuss changes with affected teammates before implementing competing interfaces. These fields describe the next episode system; they do not replace the existing attempt schema yet.

- Episode: `schema_version`, `episode_id`, `mode` (mock/live), `started_at` UTC, `calibration_version`, `status` (recording/completed/aborted/incomplete), `observed_outcome` (success/failure/unknown), `artifact_refs`.
- Observation: `observation_id`, `episode_id`, capture time, RGB/depth artifact references, camera frame, intrinsics reference, calibration version. Explicitly record missing depth and timing uncertainty.
- Proposal: episode and observation IDs, block label, pose with explicit frame + mm/deg, uncertainty, model/provider version. A proposal is data, never an executable robot command.
- Event: immutable `event_id`, episode ID, timestamp, type, payload, source (human/model/sensor/mock).
- Trajectory: episode ID, planned/measured kind, ordered samples with times, explicit joint units and pose frame/units. A log must reveal missing samples.
- Artifact: ID, relative local reference, SHA-256, media type, capture time and upload status. No embedded images in ordinary metadata documents, secrets or absolute developer-specific paths.

RGB-D collection (SKY-66, implemented in `rgbd.py` / `pipeline.py` / `candidate_store.py`):

- Observation v1 adds `setup_id`, `alignment {status: verified|unverified|unknown, method, checked_by, checked_at, calibration_version}`, `timing {clock_source, per_image_timestamps, rgb_depth_skew_ms, uncertainty_note}`, `dimensions_equal` (a fact, not registration), `intrinsics {rgb, depth}`, depth `{unit: mm, scale_m_per_unit, invalid_value, dtype: uint16}`, artifacts with `sha256`/`bytes`/`width`/`height`. Observations are immutable once saved.
- Calibration registry: operator-recorded verdict per `setup_id` and `calibration_version`; software never infers alignment. The registry's current version is part of the processing identity.
- Candidate v1: `candidate_id = cand_ + sha256(observation_id|processing_version|mask_index)[:20]`; `phase`; `bbox` and `crop_transform` in RGB pixels; `exposure {status: exposed|occluded|unknown, score, reasons[], label_source: heuristic}`; `pickability {status: unknown}` always (heuristic; grasp eligibility is SKY-87); at upload the human verdict is attached separately as `pickability_label {status: pickable|not_pickable, label_source: human|human_default, reviewed_by, reviewed_at}` plus `pickable` boolean (default pickable until the operator flips it); `depth_stats` and `depth_crop_png` only under verified registration; `segmentation {provider, model_version, segmentation_key}`; `encoder_version`, `embedding_dimension`, `embedding_input_parts` (default `["image"]`: the vector is the context crop only), `description_text` + `description_template` (geometry summary kept as metadata, not embedded); `processing_version`; `calibration_version`. Vectors and PNG bytes live in checkpoint files locally and inline in the Atlas candidate document.
- `processing_version = sha256(effective_config.json)[:16]` over pipeline code version, every segmentation request parameter, exposure parameters including block dimensions and their verified flag, cutout settings, embedding model/dimension/template hash/preprocessing, and calibration content hash plus registry current version.
- Remote: `observations` and `candidates` insert-only with read-back; `artifact_sync` mutable with `remote_status` moving only pending -> synced; media in GridFS `rgbd_media` under per-attempt ids with the SHA-keyed insert-only `media_manifest` deciding the canonical copy.

Proposal agent (AGENT-01, draft additions implemented offline in `retrieval.py` / `grasp_geometry.py` / `placement.py` / `proposal.py`; review before treating as agreed):

- Geometry calibration (separate from the alignment registry): per `setup_id` and version, `support_surface {z_in_robot_base_mm, sign_convention: positive_above_robot_base_origin, verified, source, uncertainty_mm}`, `extrinsics {rotation 3x3, translation_mm, frame_from: camera, frame_to: robot_base, verified, source, pose_time}` applicable at capture time, `finger {open_gap_mm, claw_thickness_mm, finger_width_mm, margin_mm, verified}`, `block {length_mm, width_mm, height_mm, verified}`, optional `workspace`. Immutable per version; software never flips `verified`.
- Retrieval evidence v1: `query_candidate_id`, `encoder_version`, `embedding_dimension`, `index {source, name, similarity}`, `score_conversion` (`cosine = 2 * atlas_vector_search_score - 1`), `policy` (cosine threshold 0.5 = Atlas 0.75, top_k, curation rules), `matches[] {reference_candidate_id, reference_observation_id, atlas_vector_search_score, cosine_similarity, curation}`, `excluded[] {.., reasons}`, `status matched|no_match|unavailable`. Curated means `pickability_label.label_source == human` and `status == pickable` (optionally `reference_set`); `human_default` never qualifies. Self and same-observation hits are excluded; the threshold is never lowered.
- Planning context v1: observation/episode IDs, `processing_version`, segmentation identity, calibration bundle with `missing[]`, `table_plane {status fitted|fitted_unreliable|unavailable, inlier_fraction, rms_mm, tolerances_mm, in_robot_base}`, per candidate `geometry` (pixel centre, image angle, length/width mm, `height_above_table_mm`, `base_point_mm` in robot_base, `base_long_side_deg`, `valid_fraction`, flags, `rejection_reasons`), `grasps[] {style middle|side|ends, claws_deg_to_long_side, shift_mm_along_long_side, tips_above_table_mm, clearance {status clear|blocked|unobservable, ...}, eligible, reasons}`, `retrieval` evidence, `ranking` (retrieval-assisted) and `geometry_only_ranking` kept separately, `placement {target, next_slot}`.
- Pick-and-place proposal v1: `candidate_id`, `grasp`, `source_pose` (robot_base, mm/deg, block top centre, long side), `destination` slot (`L<layer>S<index>`, block centre, `long_side_deg`, `support_z_mm`, `release_z_mm`, `requires_filled`, `validation_status`), `evidence` (retrieval status/best cosine/reference IDs, geometry quality, clearance, calibration identity), `rationale`, `decided_by`, `validation_status: validated_offline`, `executable: false`, `expiry {policy: undefined}`. Or an `abstention {reason, details}`. Historical poses are never proposal coordinates.

Data owner supplies recording/replay consumer. Vision supplies observations and proposals. Hardware validates actual resource names and frames. Keep mock fixtures unmistakably synthetic. Runtime schema and serialization tests belong to DATA-01 and VISION-01; this file alone is not validation.
